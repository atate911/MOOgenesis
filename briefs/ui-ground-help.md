# Brief: Landing/ground combat/bombardment scenes, event presentations, Help overlay & Almanac

**Read `briefs/_ui-common.md` first.** Specs: `research/06-ui-presentation-audio.md` §5.3 (colonisation landing animation), §6.3 (bombardment), §6.4 (landing / ground combat), §7.2–7.3 (notice boxes, tutor pop-ups), §10 (help system: F1 overlay of annotated boxes, no tooltips in the original), §15 appendices (hotkey sheet, screen inventory); `research/03-ships-combat.md` §5, §7 (what bombardment/invasion do); `js/sim/ground.js` (another agent: `Ground.bombPreview`, `Ground.invade` → result record `{attacker, defender, planet, landed, defenders, rounds, survivors, captured, success}`; read its header when it appears), `Gfx.Scenes.surface`, `Gfx.Fx`, `Audio` cues, `js/data/text.js` (`tips`, `advisorLines`, `planetFlavor`).

## You own
`js/ui/landing.js` (`MOO.UI.Ground` + `MOO.UI.Landing`), `js/ui/help.js` (`MOO.UI.Help`, screen `help`).

## API
1. **`MOO.UI.Landing.colony(planetId) → Promise`** — the landing animation after a colonisation "Yes" (backdrop by planet type via `Gfx.Scenes.surface`, a colony ship descends and lands, short text, year/race header, music), then a rename-your-planet prompt (order `rename`). `flow.js` can call it after the colonise answer — expose it and tell the lead.
2. **`MOO.UI.Ground.show({result}) → Promise`** — the invasion scene (turn interrupt `ground`): phase 1 transports slide down with counts ("n of N transports", attacker race, defender numbers), phase 2 two grids of tiny soldier sprites (15 per row) with death markers as rounds from `result.rounds` play out with gunfire SFX, phase 3 result text (planet captured / invasion failed, facilities captured, **list of stolen technologies**); Space/click skips. `MOO.UI.Ground.bombardPrompt({planet, preview}) → Promise<bool>` (planet map + pop/factory numbers + Bomb/Cancel) and `bombardResult(r)` (explosion animation + "population killed / factories destroyed").
3. **Help**: `MOO.UI.Help.overlay(screenId)` — F1 on any screen freezes it and draws annotated boxes with leader lines pointing at the widgets (you define the page content per screen: control screen, colony panel, planets, fleets, design, tech, races, galaxy map overview, combat…; use `data-help` attributes you may ask other screens to add, or CSS selectors), chained pages, any key closes. Provide a registry `MOO.UI.Help.register(screenId, pages)` so other agents can add pages. **Almanac screen `help`**: modern encyclopedia with tabs Races (traits, hooks, relations), Technology (all techs by field with levels/costs/effects from `Data.Techs`), Ships & components (from `Data.Components`), Planets & stars (types, growth classes, specials, star colours), Rules (economy, research, combat, diplomacy, council — concise accurate summaries of the verified rules in research/04/05), Controls (hotkeys), Tips (`Data.text.tips`). Search box. Contextual **tutor pop-ups** (Simple/Easy only, one-time, remembered in `Settings`) per research/06 §7.3.
Hook the F1 key globally (`UI.bindKey('F1', …, {modal:true})` — coordinate by exporting `MOO.UI.Help.install()`; the lead calls it at boot).
Test via the dev URL (`?dev=1&screen=help`) and console calls with fixtures.
