# Brief: Art direction v2 — "serious sci-fi" (research, style guide, theme prototype)

## Why
Product-owner directive (verbatim): *"I want to make another pass to look at the graphics, and make them more modern, like a serious game, less cartoonish, and with more of a serious scifi flair."*
The first pass (indigo/brass "imperial observatory", stylised procedural portraits/scenes/ships) is functional and pretty but reads as storybook/cartoonish in places (character portraits, the GNN anchor, ship silhouettes, ornate brass chrome). You define the NEW direction and prove it is achievable in our stack; the lead will then fan out implementation agents per module. Everything stays **original** (never copy any game's or film's assets; describe styles in words, use general principles).

## Constraints (do not break)
Vanilla JS, Canvas2D with optional WebGL2 accelerators (`Gfx.GL`, `GLPlanets`, `GLSpace`, `GLFx`) and Canvas2D fallbacks; adaptive quality via `MOO.Perf.q`; runs from file://; no network at runtime (web fonts are optional with system fallbacks); keep the original's information design/layouts (research/06) — this is a re-skin and re-rendering, not a redesign of flows. Look at CONVENTIONS.md "Look & feel" for what exists now (tokens in `css/base.css`/`css/kit.css`; per-screen CSS via `UI.css`).

## Part A — critique the current look (evidence)
Screenshot (own browser tab, 1280×720 + 1920×1080; `read_console_messages` clean) and critique: title (`index.html`), New-game wizard, galaxy screen (`?dev=1&screen=galaxy&…`), colony panel, design editor, tech screen, ledgers, GNN (`tools/test-gnn.html`), portraits (`tools/test-portraits.html`), ships (`tools/test-ships.html`), scenes (`tools/test-scenes.html`), planets (`tools/test-planets.html`, `tools/test-glplanets.html`), space/nebula/FX (`tools/test-glspace.html`), icons (`tools/test-icons.html`). For each: what makes it cartoonish/ornate/soft, ranked by impact (shapes, outlines, saturation, flat gradients, proportions, lighting, typography, ornament, motion).

## Part B — the style guide → `research/09-art-direction.md`
Concrete and implementable: 1) pillars + mood words (grounded hard-sci-fi, industrial, cinematic, restrained colour with purposeful accents, high information density, tactile) and what to avoid; 2) colour system (neutral ramps, accent semantics preserved: gold = BC, ember = industry, cyan = research, rose = danger/war, violet = diplomacy, teal = ecology, azure = ships/defence — re-tuned, desaturated/darker where needed; dark + optional light-on-dark HUD accent; contrast ≥ WCAG AA); 3) typography (technical display + condensed UI + tabular mono for numbers; offline fallbacks; sizes/tracking/case rules); 4) UI chrome language (panels, borders, corner details, dividers, buttons, sliders, tables, tooltips, modals, scrollbars, focus rings, state colours; micro-motion & sound pairing; scanline/noise/vignette/glass rules; what replaces the brass ornament); 5) iconography (stroke weight, grid, corner style); 6) rendering rules for art modules — lighting model (key/fill/rim, filmic tone mapping, exposure, bloom thresholds, volumetrics, fake AO), materials (hard-surface metal/ceramic with panel lines, emissive trims, weathering; organic skin/fur/scale/chitin with believable micro-detail; glass/holo), atmosphere (film grain, vignette, lens effects used sparingly), planets/space/nebulae realism targets, effects (beams, missiles, explosions: fireball + debris + shockwave + glow with correct HDR falloff), cinematography (camera, depth of field, composition) for portraits, scenes, battle, GNN studio; 7) per-module upgrade plan — for every file in `js/gfx/*.js`, `js/ui/*.js` with art, `css/*`: what changes, rough effort, dependencies, test page to update, risk, and which parts the GPU should render; 8) performance budget per tier; 9) acceptance checklist the lead can screenshot-test.

## Part C — prove it (prototype, don't ship)
Add a **theme layer**: `css/theme-v2.css` (new tokens + overrides of kit classes; activated by `?theme=v2` or `Settings`; the lead merges it into `base.css/kit.css` later) and build `tools/test-style2.html` showing the new chrome on real kit widgets (panel, buttons, sliders, tabs, table, modal, tooltips), plus 3 art prototypes proving the rendering approach is feasible: (1) one **portrait** (human leader, and one alien) rendered with the new lighting/material approach (Canvas2D, optional GL), (2) one **ship** hard-surface render, (3) one **scene/HUD composite** (e.g. the galaxy HUD or the lab scene). Put prototype code under `tools/proto/` (not in `js/`). Measure ms/frame at each Perf tier. Try several approaches quickly and keep the best; document what failed.

## Output
Files: `research/09-art-direction.md`, `css/theme-v2.css`, `tools/test-style2.html`, `tools/proto/*`. Final reply ≤150 words: the direction in 3 sentences, what is proven, biggest risks, recommended implementation order and parallel split.
