# AI implementation — common brief (read by every AI agent)

Product-owner priority (verbatim from the user): *"Make sure to spend extra time ensuring the mechanics, balance, gameplay, and strategy of the game are accurate … Also make sure the competing races have their own correct competitive play logic at the difficulty selected."*
So: the AI must play the way the 1993 *Master of Orion* AI plays — same structure, same cadence, same randomness, same per-objective / per-race / per-difficulty behaviour — and it must be **measurably** so (tests + soak numbers), not "plausible".

## Specs (VERIFIED research; your source of truth)
`research/07-ai-economy-expansion.md` (economy, expansion, research, ship design, difficulty, scouting) and `research/08-ai-military-diplomacy.md` (war, fleets, invasion, defence, tactical AI, espionage, council); also `research/01-races.md` §5, `research/04-galaxy-economy.md`, `research/02-technology.md` §6 where cited.
They describe the **1oom "Classic" AI** (the faithful reimplementation of the v1.3 executable). The 1oom source is GPL: it is a *reference for rules and numbers only*. **Never copy or transliterate its code**; implement from the research text in your own words and structure. You may re-check a detail on github.com/1oom-fork/1oom (`src/game/game_ai_classic.c` etc.) when the doc is ambiguous — note it in your report.
The research docs mark confidence: `[C]` verified twice, `(unverified)`, `(conflict …)`, `(BUG)`. For anything unverified, choose the behaviour that matches the strategy-guide intent and record the decision in your notes file.

## Framework (read `js/ai/ai.js`, `js/ai/ctx.js`, and the two finished examples `js/ai/planets.js`, `js/ai/research.js`)
* An AI plans as a **pure function** `AI.plan(snapshotS, empireId, seed) → orders[]`. `S` is a **read-only** snapshot (in production it is `MOO.snap` inside a worker thread); never mutate it. No `Math.random`, no `Date` — randomness only from `ctx.R` (`R.int(a,b)` inclusive, `R.chance(p)`, `R.pick`, `R.shuffle`…). Same snapshot + seed ⇒ identical orders.
* Steps register with `AI.step(name, order, fn(ctx))` and run in ascending `order`; each step is wrapped in try/catch (errors land in `ctx.errors`). Step table (the original p1 → p2 → p3 sequence):
  `10 intel` · `20 scouts` · `25 colonize` · `30 military` · `40 economy` (population transports, panic/developing funding, tax) · `45 designs` (original p2) · `50 planets` (original p3 sliders) · `60 research` · `70 spy` (security/spies) · `80 diplomacy` (only if glue is needed).
* **The AI is omniscient about the map like the original** (it reads every empire's planets/fleets directly — fog of war does not apply to it); the only geometric gate is fuel range (`ctx.range(star)` = my `E.frange`, 0 out / 1 in range / 2 range with fuel tanks).
* `ctx` helpers: see the header of `js/ai/ctx.js`. Planned-state helpers (`ctx.sliders/setSliders/build/setBuild/reserve/fund`) let later steps see earlier steps' decisions; `ctx.shared` is the hand-over scratch between steps — **document every field you put there in your file header** (other agents read it). Because planners are pure, emulate the original's in-place side effects with bookkeeping in `ctx.shared`: ships already committed this plan, fleets "in flight" counted so far, targets marked used, etc.
* Persistent AI memory = `E.ai` via `ctx.patch({…})` (becomes one `aiState` order). Keep it small, plain JSON (countdowns, design ages, role indices…).
* **Quirks:** the original has documented bugs/quirks. Policy: pure defects (inverted signs, index mix-ups, dead code, the 4th-colony-ship curse…) are implemented **fixed by default** but guarded as `AI.QUIRKS.<name> = false` (register at load: `AI.QUIRKS.fourthColonyShip = false`) and the original behaviour runs when `ctx.quirk('<name>')` is true (the option `S.settings.options.aiClassic` flips them all). Quirks that shape the observable feel of the AI (it gangs up on the leader, invades with half-population transports, never uses rally points, conjures colony ships, builds random designs…) are implemented **as the original**. Put the full quirk list (name, default, what it does, spec § ) at the top of your file.
* **Difficulty / personality / objective / race** must each change behaviour exactly where the spec says (use `ctx.diff` 0..4 = Simple, Easy, Average, Hard, Impossible; `ctx.pers`, `ctx.obj` indices into `AI.PERS`/`AI.OBJ`; `ctx.rd`/`ctx.aiMod` = `Data.Races` record + its `ai` hooks). Don't invent behaviour the spec doesn't have.
* Orders you can emit are in `DESIGN.md` B4 (+ `js/sim/*.js` `Orders.register` calls). A missing order you need: register it yourself from your own module with `MOO.Sim.Orders.register('type', (S, E, o) => …)` (validate it like a human order would be validated, never trust the planner) and say so in your report. Sim files are not yours — if you find a defect in `js/sim/**` or `js/data/**`, describe the exact fix in your final report instead of editing.

## Testing & verification (mandatory)
* Rules tests in `tools/rules/<NN>-<name>.test.js` (see `tools/rules/40-colony.test.js` for the format; run `node tools/rules-test.js <area>`; keep the whole suite green). Load the sim via `tools/headless.js`. Test: determinism, purity (the snapshot is untouched — compare a JSON hash before/after `AI.plan`), exact spec numbers at boundary values, Monte-Carlo frequencies of every random roll (≥10 000 draws, within tolerance of the documented probability), per-difficulty / per-objective / per-race differences.
* Behavioural checks over real games: `Sim.autoPlay`/`tools/soak.js` (24 threads — read `tools/SOAK.md`; `node tools/soak.js --games 48 --difficulty average --replay …`). Report concrete numbers (colonies / production / techs / ships at turns 25/50/100/150 per difficulty; wars; conquests) and explain any deviation from what the research predicts (e.g. research/07 §1.5 early timeline, §9 playbooks). Fix what you can in your own files.
* Performance: one `AI.plan` ≤ 5 ms median on a 108-star, 6-empire mid-game (measure; it runs on a worker but the soak plays thousands of games).
* Notes file `tools/ai-notes/<your-area>.md` (≤ 100 lines): spec § → implemented where; quirk flags + defaults; measured numbers; known gaps. The lead merges these into the project docs.
* Final reply to the lead: **≤ 150 words** — files, what is implemented / not, quirk flags, measured numbers, anything needed from other modules (exact patch descriptions for sim/data files).
