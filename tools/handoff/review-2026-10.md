## P0 — the stuck-turn ("Year … spinner") class · FIXED on branch `fix/turn-flow-robustness`

Root cause (CONFIRMED, reproduced in Chromium): the turn waits on a side-panel prompt (explore / colonise card,
pre-battle choice, battle result). Leaving the galaxy screen (bottom bar, D/F/M/R/P/T, F2–F5) and coming back made
`enter()` re-show the default panel, which replaced the prompt without resolving it. The interrupt's Promise then
never settled; only "Skip this step" ended the turn — and a skip answered `undefined`, which the sim treats as
**accept** for audiences (can declare war on a third empire or break an alliance) and **bomb** for the bombard prompt.

What the branch changes:
- `UI.Side.hold/release/showHeld/drop` (js/ui/galaxy.js): a held panel cannot be replaced and is re-shown on re-entry.
  `Flow.card` (js/ui/flow.js) and combat's pre-battle / result panels (js/ui/combat.js) hold their panel.
- `UI.attention(btn)` + `.needs-answer` (js/ui/kit.js, css/kit.css): the one control that moves the game forward is
  highlighted (pulsing ring) and focused, so Enter/Space answer it. Wired into cards, pre-battle, battle result.
- `Game.endTurn` (js/core/game.js): tracks `Game.pending`; `Game.abortTurn()` is called by load / quit / new game so
  `Game.busy` can never stay stuck on an abandoned turn; an exception in the pipeline no longer autosaves the
  half-processed state and is reported with a toast; skipped steps answer the harmless choice (`SKIP_ANSWERS`).
- Navigation is locked while a turn runs (toast says what is pending); F2–F5 ignored; game menu Save/Load/Quit are
  disabled with the reason; Next turn / nav buttons dim.
- Hotkey dispatch (js/ui/kit.js): the most recent binding wins — the colonise card's **N** was swallowed by
  "Next turn", galaxy **F3** (cycle colonies) by the perf overlay.
- Side-panel render errors fall back to the default panel (fleetDeploy with `star:-1` used to blank the panel);
  `moveOrder` ignores fleets in flight; title-screen Continue reports an unloadable save.

Verified: freeze repro now completes; mid-turn quit → new game works; `tools/qa/turns.js` 40 turns clean;
`tools/qa/fuzz.js` 2,796 actions clean; rules tests green.

Still to do in this class (not yet in the branch): fix the sim-side defaults at the source (P1 #1–#2 below) so headless
and AI-played humans get the same safe answers; decide the council-verdict abort rule (P3 #38); give every scene the
same highlight (P3 #38). Known non-hang that *feels* like one: animations run on requestAnimationFrame, so a battle,
GNN or landing scene pauses while the browser tab is hidden and resumes when it is fronted — a "paused" label would
reassure.

## P2 — hitches, stalls and performance (graphics / workers / loader)

22. **high · js/gfx/planets.js:1592 `renderSprite` · CONFIRMED** — the Canvas2D planet sprite generates its texture
    tier synchronously on the main thread: 150 ms (128 px) to 654 ms (240 px) per unique planet in Chromium. On the
    'low' tier, GPU off, or while shaders still compile, opening a colony card / tech screen / combat freezes the UI for
    0.2–0.7 s per planet. Fix: draw `bestTex || requestTex(P,128,true)` and queue the wanted tier async (as `draw`
    does), re-render when it lands. Same at :1549 for the first draw (30–108 ms per look; a zoom onto 5 new planets ≈
    250 ms in one frame).
23. **high · js/gfx/gl-planets.js:1151–1158 `supported()` · CONFIRMED** — links the rocky shader synchronously
    (`LINK_STATUS`) on first use: the first galaxy frame stalls for the whole compile (0.3–2 s on real drivers).
    Fix: return false while pending and let the CPU fallback draw.
24. **high · js/main.js:16–20 + gl-space.js:833 + gl-fx.js:1103 + gl-planets `buildNoise` · CONFIRMED** — the three
    warm-ups 250 ms after boot compile 17 programs synchronously and run 250 ms of noise building; measured long tasks
    of 0.3–2.8 s at boot. Fix: `KHR_parallel_shader_compile` + polling (gl-planets already has it), noise in a worker /
    idle slices, stagger the warms.
25. **medium · js/core/workers.js:117–128 · CONFIRMED** — the 30 s job timeout starts at enqueue, not dispatch: on a
    1-worker device a queued `aiPlan` is re-run inline (main-thread freeze) while the worker also runs it; a running job

26. **medium · js/loader.js:5 + deploy templates · CONFIRMED** — `?_=Date.now()` on every file every load defeats HTTP
    caching: 3.9 MB JS + CSS re-downloaded on every visit; the nginx/caddy `no-cache`+ETag revalidation never happens.

27. **medium · js/gfx/scenes.js:3773 + js/gfx/grade.js:33–62 · PLAUSIBLE** — the colour-grade pass rebuilds a radial
    gradient and a pattern every frame and does ~5 full-screen passes (the cache `key` at grade.js:48 is computed and
    unused). Fix: cache tone/vignette per size, keep only grain per frame.
28. **medium · js/gfx/scenes.js:106–118 · PLAUSIBLE** — a scene's first draw builds all layers synchronously (0.8–1 s
    on software GL; ~150–400 ms on hardware). Fix: build over idle callbacks / prewarm.
29. **medium · js/core/perf.js:76–78 · PLAUSIBLE** — on software GL the tuner raises to 'medium' (GL on), collapses,

30. **medium · js/gfx/gl.js:19–38 · PLAUSIBLE** — context loss recreates the canvas instead of waiting for

31. **medium · memory budgets · PLAUSIBLE** — scenes 480 MB + worldart 160–480 MB + planet textures 120 MB + sprites

32. **low** — pool size `hardwareConcurrency−1` up to 32 (31 workers × 669 KB blob + 31 snapshot parses); Google Fonts

## Phase 2 proposal — "select and move on" (smoothness, from the user's play notes)

The complaint: many actions take several clicks in different places, and it is not always obvious what an input
screen wants. The `UI.attention` highlight on the branch is the building block; the flows to collapse:

- **Fleet orders**: today select fleet → click/right-click destination → Accept (and ship-count sliders). Make a
  right-click on a star with a selected fleet *send* immediately (range-checked, toast on failure), keep Accept only
  when counts were edited; show ETA on hover before the click.
- **Colonise**: card Yes → landing vignette → Continue → default panel. Offer "Yes, and skip the landing" as the default
  (Space), remember it as a setting; auto-close the vignette.
- **Combat**: pre-battle card → Fight/Auto → result card → Continue. Add a per-game "always auto-resolve when odds ≥ X"
  toggle on the card, and let the result card auto-dismiss after the summary unless the player hovers it.
- **Tech choice**: a full scene for a one-line pick; the scene already has "Decide for me". Default the highlighted
  choice to the cheapest and make Space confirm it immediately (it does on the branch); consider a compact side-panel
  picker when `animSpeed === 0`.
- **GNN**: 49 of 76 bot clicks in a 40-turn game were "next" on GNN. Group the turn's items into one page with a single
  Continue, and auto-advance with a readable delay.
- **Colony management**: sliders re-render the whole panel on every tick; keyboard control is dead (P3 #33). Add
  "apply this slider layout to all colonies of type X", and a one-key "Trans / Reloc to the selected star".
- **Visible next step**: every input screen marks exactly one advancing control with `UI.attention` and lists its keys
  in the footer (cards: Y / N / Space; scenes: Space / Esc); the galaxy bottom bar shows "Waiting for: …" while the turn
  runs (the branch toasts it; a persistent label is better).
- **Fewer confirmations**: Overwrite-save and Load confirmations are right; "End the turn?" should only fire when the
  option's own text says (idle colonies / unassigned research) — P3 #36.
