# Polish pass — October 2026 (branch `claude/polish-pass`)

Brief from the product owner: make the game look more polished on PC and phones "while retaining the soul of the game". A
screen-by-screen capture (`tools/qa/art-shots.js` at 1920x1080, `tools/qa/phone.js` in portrait / landscape / small) gave the list
below; every item is done on this branch. Nothing changes the rules, the flows or the original's layout.

## What changed, and where

## Galaxy map thinning (same branch, third commit)

The owner's brief: the control screen looked congested; negative space matters; simpler wins when it is equal or better, gameplay
never compromised. `galaxymap.js`: `overview()` = `cam.z <= fitZ * 1.4` (the whole-galaxy chart; past it the map is an inspection).
In the overview: names for owned stars, the selected / hovered one and Orion only (`drawLabels`, the `auto` mode); colonisation glyphs
(`habShow`) only on stars within fuel range (`sd.near`, from `E.frange[star] === 1`) plus the hot star; everything as before once
zoomed in. Always: one owner ring (the 0.28-alpha echo ring is gone; Empire marks keep their double for the white banner), the scan
ring at 0.34 alpha with no sweep pulse, the grid + ruler off by default (`Settings.mapGrid: false`, both platforms), a 0.5rem gap
between the view and layer groups of the control column. Not touched: the nebula and territory intensities (the GL path cannot be seen
on software rendering here), fleet markers, badges, the HUD.

## Harmony and art (same branch, fourth commit)

The owner's brief: make the elements and screens congruent, the best of each winning; then go over how the art is used (some
inconsistencies, scaling that is sometimes soft).

| Item | Files | Notes |
|---|---|---|
| One title gold | `css/theme-v2.css` (`--title-hi`, `--title-shadow`), restyle blocks of `ledger-fleets.js`, `ledger-planets.js`, `overview.js`, `tech.js` (`.tch-title, .rx-title, .ttp-head h1`) | Every tool screen's title is `var(--title-hi)` (#ffd36a) with the same two-step shadow and glow; Research / Races / Report / Tech tree had #ffc04a with a 1px shadow. `--title` (#e8c860) stays the indigo plates' gold. |
| Box titles | `ledger-planets.js` (`.lp-bt`), `overview.js` (`.ov-kt`), `css/theme-v2.css` (`--head-orange`) | The box-title tier is the original's orange (#f48201, `.rx-bt`, `.ov-kt`, now `.lp-bt` too, which was mint) in caps; the in-map legend head `.gl-h` (galaxymap.js) is caps as well, its subtitle not. |
| Slider readouts | `css/theme-v2.css` (`.slider .s-val`, `--slot-ink`) | #f0e060 in the recessed slot everywhere (the colony panel already was, by its local `--amber`); the theme's `.readout` wells and the Research total keep lime / green (RP). Phones keep their own skin. |
| Ledger thumbnails | `ledger-fleets.js` (`.lf-pic`) | The planet tile takes the moving-fleet tile's recessed ring, which is the Planets ledger's `.lp-orb` ring. |
| `WorldArt.image()` | `js/gfx/worldart.js` | `image(path, {fit, fx, fy, alpha, alt})` returns an `<img>` (inline `display:block; width/height:100%; object-fit; object-position`), hidden on a load error, no src when art is disabled. The browser samples the 1254² / 1920×1080 source at the box's device size, so it is sharp at DPR 2 and at a 4K interface scale, and one decode serves every box. `canvas()` stays for canvas drawing (scenes, the design editor) and for the procedural fallbacks. |
| DOM art sites → `<img>` | `side-colony.js` (planet thumbnail, build-box yard, wide planet box, postcard), `side-misc.js` (thumbnail, wide box), `ledger-fleets.js` (`planetPic`), `ledger-planets.js` (`orbThumb`), `races.js` (Not Present void, Report dossier), `setup.js` (homeworld), `landing.js` (event plate), `css/phone.css` (`.ph-thumb`) | Every selector that sized the canvas is now `:is(canvas, img)`, so the procedural fallbacks (art off, no art for a type) still fit. |
| Ship cells | `ledger-fleets.js` (`shipCanvas`, `paintFleets`), `combat.js` (`shipCanvas`) | Was: a 147×80 store (220×120 / 1.5 at DPR 1) with the sprite enlarged up to 1.6× inside it. Now: the cell is measured after mount (device pixels) and painted at that size; a 64px probe render (cached by the sprite cache) gives the hull's aspect, and the sprite is rendered so it fills `HULL_FIT` of the box on both axes; never upscaled (`k ≤ 1`). Off-screen (no layout) the old store size is used. |
| First-landing scene | `flow.js` (`scene: 'first-landing'`), `side-misc.js` (card `p.scene`) | The colonise card's wide box shows `scene/scene-first-landing` (unused since it was made) with the type / POP / minerals stack over it; the scout's report before it showed the orbit plate. |

Audit notes (not changed): the 3/4 ship renders exist only for variant 1 of each class, so a design on variant 2 or 3 shows a top-down
sprite on the pre-battle card next to 3/4 ones (needs art); tooltips are indigo on every screen, including the brown family, which reads
as intended (the kit's one tooltip); `scene-first-landing` is a rocky sunset whatever the planet type (acceptable for a generic
"landing", noted in case a per-type set is made). Unused art after this pass: none in `assets/art/`.
