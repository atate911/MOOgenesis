# Phone layout layer — October 2026 (branch `claude/phone-mode`)

The game now plays on a phone. Desktop is untouched: every phone rule is gated on `<html data-phone>`, and
`tools/qa/layout-fingerprint.js` shows identical desktop layouts to `main` (3 window sizes × 17 screens).

## How it is wired

| Piece | Where | What it does |
|---|---|---|
| Gate | `index.html` inline script | `window.MOO_PHONE` + `<html data-phone>` before any CSS loads: coarse pointer AND `min(screen.width, screen.height) ≤ 600` (phones in either orientation; tablets keep the desktop layout). `?phone=1` / `?phone=0` force it. |
| Load-time value | `js/core/phone.js` | `MOO.Phone.boot / active() / forced`. Headless-safe (off in Node). Perf, workers and audio read it **once at start-up**. |
| UI plumbing | `js/ui/phone.js` | The app bar + Back control, history sentinel, long-press tips, `UI.Phone.sheet()` and `UI.Phone.stepper()` widgets, F1 overlay off, autosave on `pagehide`. |
| Galaxy | `js/ui/phone-galaxy.js` | Side panel → bottom sheet (strip / half / full) driven by a `UI.Side.show` wrapper; map overview key → sheet. |
| Ship design | `js/ui/phone-design.js` + 3 hooks in `design.js` | Re-arranges the editor's own containers; card picker; weapon steppers; library sheet. |
| Rules | `css/phone.css` | Every rule under `html[data-phone]`; `html:root:root[data-phone]` where a bumped (`:root:root`) restyle must lose. |

**Back.** One control dispatches a synthetic `Escape` keydown: every screen, modal, popup and panel already handles Escape exactly
like its right-click, so nothing per-screen was needed. The Android/iOS back gesture pops a single history entry (re-armed on the
next real tap, never inside `popstate`) and does the same. On the title screen the entry is not armed, so back leaves the page.
The control lives in a slim app bar on every screen except the map, the menu and the design editor (`UI.Phone.backHidden`);
`<html data-ph-bar>` is set before a screen's `enter()` (Screens.go is wrapped) so canvases measure their final size.

**Combat.** Phones never open the tactical screen: the pre-battle card offers Retreat and Auto only (`combat.js` buildPreBattle),
`Combat.fight` maps a fight to auto, and the combat screen's `enter` auto-resolves and returns if a phone lands on it.

**Perf / audio / workers.** `TIERS.phone` (dpr 2, GL on, few particles) sits outside `ORDER`: the governor never climbs into it and
leaves it only for `low` after 3 slow seconds; a phone on a software renderer starts `low`. Worker pool capped at 2. The sampled
orchestra is off (its 840 files decode to hundreds of MB; iOS kills tabs near 384 MB) — the synth voices play.

**Installable.** `manifest.webmanifest` + `assets/icons/*` (rendered by `tools/make-icons.js`) + Apple tags in `index.html`.
No service worker. The save server's gate lets the manifest and icons through (browsers fetch them without cookies);
`scripts/lib.sh` deploys both; the nginx template serves the manifest with its type.

**Desktop one-liners** (all no-ops unless `MOO.Phone.active()`): `combat.js` (card, fight, screen enter), `options.js` (battle rows),
`flow.js` (brief news), `design.js` (renderPopup hand-over, row hook, `UI.Design._phone`), `system.js` (`geometry()` portrait),
`tech.js` (`layoutScene` portrait), `spyscenes.js` (tap to read, tap again to steal), `races.js` (tap highlights on Racial stats),
`workers.js`, `sampler.js`, `perf.js`. Shared files: `js/manifest.js` (5 entries), `js/ui/kit.js` (`UI.tipHtml` export).

## Testing

```
node tools/qa/phone.js                 # portrait phone: gate, galaxy sheet, battle cards, 17 screens, scenes, menus, design editor,
                                       # Back + hardware back, long-press tip, 4 bot turns; then a desktop regression pass
node tools/qa/phone.js landscape       # the same on an 844×390 phone
node tools/qa/modes.js phone phoneland # the robustness matrix (8 bot turns) on phone profiles
node tools/qa/layout-fingerprint.js > a.json; node tools/qa/layout-fingerprint.js <main checkout> > b.json; diff a.json b.json
```
Screenshots land in `$SHOTS` (default `/tmp/claude-0/phone`). The emulated phone renders in software, so it runs the `low` tier;
on a real phone GPU it is `phone`. Known console noise the QA filters: offline web fonts, software-GL driver chatter,
`assets/art/still/inst-spaceport.webp` (listed in ART-NEEDED.md), and `api/status` on a static server.

## Accepted losses on phones

Keyboard-only actions with no touch equivalent: F4/F5 (colonies with ships), Shift+I (attention backwards), Home, F3 overlay (use the
`perfOverlay` setting), Ctrl± research nudge, GNN previous story (phones get the brief list), F1 context help. Covered by existing
buttons: colony cycling (title arrows), attention forward (HUD chip), relocate-all (Reloc › All colonies), Esc-clears (Back), hull
1–4 / B / C, double-clicks. Canvas hover tips (galaxy map stars) do not show on touch; tapping selects instead.

## Follow-ups — found during the review, not done (most valuable first)

1. **Real-device pass.** iOS Safari: WebGL2, blob-URL workers, safe-area insets, the edge-swipe back (expect a brief same-page
   flash), Add to Home Screen. Android Chrome: hardware back, install prompt. Memory with world art on a 3–4 GB phone.
2. **Phone layout toggle in Options** (Auto / On / Off, persisted). The gate is screen-size based; a foldable, a big phone or a
   tablet owner may want the other layout. Today only `?phone=1|0` overrides it.
3. **Touch wording for keyboard hints.** Still keyboard/mouse text on phones: research ("Click a name to lock it · wheel or +/− to
   nudge · = equalises"), council / endings / landing ("Space next · Esc skip"), the research choice ("↑ ↓ choose · Space research ·
   Esc cancel"), audience number and Esc badges, Options ("Esc or right-click to go back", "Tooltips: Hover hints…"), the system view
   ("Click or press any key to return"). One `UI.hint()` helper that knows about touch would cover them.
4. **Bottom-bar discoverability.** Races, Planets and Tech sit off-screen to the right of the scrolling bar. An edge fade, or a
   "More" button folding the last three, would make them findable.
5. **Long-press on a map star** to show the galaxy map's own star tooltip (planet type, owner, range), which hover shows on desktop.
6. **Opt-in high-quality music** on phones: per-track lazy loading of the sampled orchestra instead of all 840 files at once.
7. **Fleet ledger as cards** (one card per stack, design chips inside) instead of the sideways-scrolling grid; the same for the
   planets ledger (one card per colony).
8. **Landscape layouts that use the width**: the design editor and the tool screens are a single column in landscape too; a
   two-column arrangement (preview | parts, sliders | project) would fit an 844×390 screen better.
9. **Ground invasion on phones**: the two soldier grids shrink to ~10 px cells; stacking them vertically in portrait needs a branch
   in `landing.js` `layout()`.
10. **A touch version of F1 help**: a "?" in the app bar opening the same pages as a sequence of cards.
11. **Design library thumbnails** are small on phones (the ship art renders at desktop card size).
12. **Asset caching** (pre-existing, matters more on mobile): art / ships / races / audio URLs carry no `?v=`, so nginx revalidates
    every file on every load. Stamping them like the JS/CSS would let them cache for a year.
13. **Caddy deploys**: the nginx template now serves `.webmanifest` with its type; check Caddy's built-in mime table does too.
14. **Service worker** (offline play, faster starts) — out of scope by decision; note `?_=Date.now()` on unstamped trees.
